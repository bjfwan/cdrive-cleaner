### 4. 核心功能设计

#### 4.1 磁盘扫描
**技术方案：**
- 使用 Windows API（FindFirstFileW/FindNextFileW）直接遍历
- 并发扫描多个顶级目录（tokio）
- 以管理员权限运行，访问系统保护文件
- 实时推送进度到前端

**性能目标：**
- 扫描速度：10,000-20,000 文件/秒
- C 盘（500GB，50万文件）：30-60秒
- 内存占用：< 200MB

**实现要点：**
1. 快速扫描：只扫描顶级目录，获取大致占用
2. 深度扫描：递归扫描所有文件，获取完整信息
3. 进度计算：基于已扫描文件数估算进度
4. 错误处理：权限不足的文件标记为不可访问

#### 4.2 文件迁移
**迁移流程：**
1. 检查目标盘空间是否充足
2. 检查文件是否被占用
3. 复制文件到目标位置
4. 验证复制完整性（校验文件大小）
5. 创建符号链接
6. 验证链接有效性
7. 删除原文件
8. 记录迁移信息到数据库

**符号链接策略：**
- **目录**：优先使用 Junction（不需要管理员权限）
- **文件**：使用 Symlink（需要管理员权限）
- **同分区**：使用 Hard Link

**失败处理：**
- 任何步骤失败，自动回滚
- 保留原文件直到链接验证成功
- 记录失败原因和详细日志

#### 4.3 安全检测
**检测层级：**
1. **系统关键路径检测** - 黑名单机制
2. **应用类型识别** - 识别游戏、便携式应用等
3. **进程运行检测** - 检查文件是否被占用
4. **文件占用检测** - 尝试独占访问
5. **注册表依赖检测** - 检查是否有注册表项

**风险分级：**
- 🟢 Safe（75-100分）：推荐迁移
- 🟡 Moderate（50-74分）：可以迁移但需注意
- 🟠 Risky（30-49分）：不建议迁移
- 🔴 Dangerous（0-29分）：禁止迁移

### 5. 数据结构设计

#### 5.1 扫描结果
```typescript
interface ScanResult {
    root_path: string;           // 扫描根路径
    total_size: number;          // 总大小（字节）
    total_files: number;         // 文件总数
    total_dirs: number;          // 目录总数
    scan_duration_ms: number;    // 扫描耗时
    directories: DirectoryNode[]; // 目录树
    inaccessible_count: number;  // 无法访问的文件数
}

interface DirectoryNode {
    path: string;                // 完整路径
    name: string;                // 目录名
    size: number;                // 大小
    file_count: number;          // 文件数量
    children: DirectoryNode[];   // 子目录
    is_symlink: boolean;         // 是否为符号链接
    link_target?: string;        // 链接目标
}
```

#### 5.2 迁移记录
```sql
CREATE TABLE migrations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source_path TEXT NOT NULL,
    target_path TEXT NOT NULL,
    link_type TEXT NOT NULL CHECK(link_type IN ('symlink', 'junction', 'hardlink')),
    file_size INTEGER NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active', 'restored', 'broken'))
);

CREATE INDEX idx_migrations_status ON migrations(status);
CREATE INDEX idx_migrations_created_at ON migrations(created_at);
CREATE INDEX idx_migrations_source_path ON migrations(source_path);
```

### 6. 性能优化策略

#### 6.1 扫描性能
**并发扫描：**
- 使用 tokio 异步运行时
- 同时扫描多个顶级目录
- 动态调整并发数（根据 CPU 核心数）

**零拷贝 IO：**
- 只读取文件元数据，不读取文件内容
- 使用 Windows API 批量获取文件信息

**内存优化：**
- 流式处理，不一次性加载所有文件
- 大目录分批处理

#### 6.2 迁移性能
**智能复制：**
- 使用 Windows CopyFileEx API（支持进度回调）
- 大文件分块复制，实时反馈进度

**并发限制：**
- 同时迁移多个小文件
- 大文件单独处理（避免 IO 竞争）

## 💡 技术决策记录

### 为什么选择 Tauri 而不是 Electron？
1. **体积**：Tauri 打包 3-5MB，Electron 50-100MB
2. **性能**：Rust 后端性能更好
3. **内存**：Tauri 内存占用更小
4. **安全**：Rust 内存安全

### 为什么使用 Windows API 而不是标准库？
1. **性能**：直接调用 API 更快
2. **功能**：可以获取更多文件信息
3. **权限**：可以访问系统保护文件

### 为什么需要两种扫描模式？
1. **快速扫描**：用户快速了解大致占用
2. **深度扫描**：获取完整信息，支持精确分析
