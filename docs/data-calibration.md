# 扫描数据校准机制

## 概述

为了确保扫描数据的准确性，系统实现了自动数据校准机制。深度扫描会构建详细的目录树结构，但使用磁盘真实使用情况作为基准进行校准。

## 校准原理

### 问题背景

深度扫描在遍历文件系统时可能会遇到以下问题：
1. 硬链接导致同一文件被多次计数
2. 符号链接或 junction points 的特殊处理
3. 系统文件或虚拟文件系统的重复遍历
4. 文件系统元数据的差异

这些问题可能导致统计的大小与磁盘真实使用情况不一致。

### 解决方案

使用磁盘真实使用大小作为基准，对目录树数据进行比例校准：

```
校准比例 = 磁盘真实使用大小 / 目录树统计大小
校准后大小 = 原始大小 × 校准比例
校准后文件数 = 原始文件数 × 校准比例
```

## 校准流程

### 1. 数据收集阶段

深度扫描会收集三组数据：

- **遍历统计**：遍历文件系统时的实时统计
- **目录树递归统计**：递归统计整个目录树的数据
- **磁盘真实使用**：通过 Windows API 获取的磁盘实际使用情况

### 2. 校准判断

系统会计算校准比例：

```rust
calibration_ratio = disk_used / tree_recursive_size
```

只有在以下条件下才会应用校准：

1. **比例在合理范围内**：0.8 < ratio < 1.2（差异在 20% 以内）
2. **差异显著**：|ratio - 1.0| > 0.01（差异超过 1%）

### 3. 校准应用

如果满足校准条件，系统会：

1. **校准总体数据**：
   - total_size = disk_used（直接使用磁盘真实大小）
   - total_files = tree_files × calibration_ratio

2. **校准目录树**：
   - 递归遍历所有目录节点
   - 对每个目录的 size 和 file_count 应用校准比例
   - 保持目录树的相对比例不变

## 校准示例

### 示例 1：正常校准

```
目录树统计大小: 191.34 GB
磁盘真实使用: 170.35 GB
校准比例: 0.8904

校准前：
  Users 目录: 77.18 GB
  Windows 目录: 37.37 GB

校准后：
  Users 目录: 68.73 GB (77.18 × 0.8904)
  Windows 目录: 33.28 GB (37.37 × 0.8904)
```

### 示例 2：跳过校准（比例异常）

```
目录树统计大小: 50.00 GB
磁盘真实使用: 170.35 GB
校准比例: 3.407（超过 1.2）

结果：不应用校准，使用原始目录树数据
原因：比例异常，可能是扫描范围不完整
```

### 示例 3：跳过校准（差异太小）

```
目录树统计大小: 170.00 GB
磁盘真实使用: 170.35 GB
校准比例: 1.002（差异 0.2%）

结果：不应用校准，使用原始目录树数据
原因：差异太小，不需要校准
```

## 优势

1. **准确性**：使用磁盘真实使用情况作为基准，确保数据准确
2. **一致性**：保持目录树的相对比例，不破坏数据结构
3. **智能判断**：只在合理范围内校准，避免异常情况
4. **透明性**：详细的日志输出，便于调试和验证

## 与快速扫描的对比

| 特性 | 快速扫描 | 深度扫描（校准后） |
|------|---------|-------------------|
| 准确性 | 高（< 1% 差异） | 高（校准到磁盘真实值） |
| 速度 | 快（30-40秒） | 慢（70-100秒） |
| 目录树 | 只有根目录子目录 | 完整的多层目录树 |
| 文件列表 | 无 | 有（所有文件） |
| 适用场景 | 快速概览 | 详细分析和迁移 |

## 注意事项

1. **校准不是万能的**：如果扫描范围不完整，校准可能无法修正
2. **保持相对比例**：校准只调整绝对值，不改变目录间的相对大小
3. **依赖磁盘 API**：如果无法获取磁盘真实使用情况，将使用原始数据
4. **适用于整盘扫描**：校准机制最适合扫描整个磁盘分区

## 未来改进

1. **分段校准**：对不同深度的目录应用不同的校准比例
2. **智能检测**：自动识别并排除虚拟文件系统
3. **缓存优化**：利用快速扫描的结果优化深度扫描
4. **增量更新**：只重新扫描变化的部分
